# 다국어(i18n) 사전 세팅 설계

- 작성일: 2026-07-30
- 대상 언어: 한국어(ko, 기준), 영어(en)
- 상태: 구현 완료

## 1. 배경과 목표

이 저장소는 여러 React 프로젝트가 가져다 쓰는 사내 공통 UI 컴포넌트
라이브러리이면서, 동시에 그 컴포넌트를 시연하는 데모 앱을 함께 담고 있다.

목표는 화면 전체를 번역하는 것이 아니라, **앞으로 추가될 화면들이 따라갈
다국어 골격을 미리 깔아두는 것**이다. 담당 개발자가 새 페이지를 만들 때
번역 구조를 고민하지 않고 기존 패턴만 따라가면 되도록 한다.

## 2. 확정된 결정

| 항목 | 결정 |
| --- | --- |
| 적용 계층 | 앱 계층에만 적용. 공통 UI는 i18n을 모르는 상태 유지 |
| 라이브러리 | `react-i18next` + `i18next` |
| 의존성 위치 | `devDependencies` |
| 리소스 관리 | 정적 JSON을 번들에 포함 (지연 로드·서버 조회 없음) |
| 언어 결정 | 기본 `ko`. 사용자가 바꾸면 `localStorage`에 저장 |
| 브라우저 언어 감지 | 사용하지 않음 |
| 이번 범위 | 인프라 + 레이아웃(topbar/sidebar) + 로그인 화면 |

### 결정 근거

**공통 UI를 i18n-agnostic으로 두는 이유.** 소비자 프로젝트마다 i18n 구현이
다를 수 있다. 공통 컴포넌트가 `i18next`에 결합되면 소비자는 자기 설정과
충돌하거나 쓰지도 않는 런타임을 떠안는다. 텍스트는 전부 props/children으로
받는다. 이는 CLAUDE.md의 "업무 도메인에 종속된 값은 공통 컴포넌트 Props에
넣지 않는다" 규칙과도 같은 방향이다.

**devDependencies인 이유.** 커밋 `1487644`에서 앱 전용 라이브러리
(react-query, react-hook-form, zod, zustand, d3, echarts)를 `dependencies`에서
의도적으로 제거했다. i18n도 앱 전용이므로 같은 기준을 적용한다.

**브라우저 언어 감지를 쓰지 않는 이유.** 사내 관리 시스템이라 한국어가
기본이어야 자연스럽다. 감지를 켜면 사용자 환경에 따라 예상 밖 언어로 시작해
오히려 혼란이 된다. 감지기 의존성(`i18next-browser-languagedetector`)도
추가하지 않았다.

## 3. 계층 경계

| 계층 | 위치 | i18n 관계 |
| --- | --- | --- |
| 공통 UI | `src/shared/ui/**` | 완전 무지. i18next를 import하지 않음 |
| i18n 인프라 | `src/app/i18n/**` | 초기화·저장·전환 UI를 소유 |
| 앱 화면 | `src/layouts/**`, `src/pages/**` | `useTranslation()`으로 소비 |

`src/shared/`가 아니라 `src/app/i18n/`에 둔 이유: `src/index.ts`는
`shared/ui/*`만 export하므로 `shared/`에 두면 "라이브러리의 일부"로 읽힌다.
`src/app/`은 이미 `router.tsx`, `lazy-pages.ts`가 있는 앱 전용 폴더다.

## 4. 파일 구조

```
src/app/i18n/
  index.ts              공개 표면 (배럴)
  locale.ts             SUPPORTED_LOCALES · Locale · DEFAULT_LOCALE · isLocale
  locale-storage.ts     localStorage 읽기/쓰기 (실패해도 앱이 죽지 않음)
  config.ts             리소스 등록 · initI18n · applyLocale
  use-locale.ts         useLocale 훅
  locale-switcher.tsx   언어 전환 UI
  i18next.d.ts          모듈 확장 → t() 키 타입
  locales/
    ko/{common,nav,auth}.json
    en/{common,nav,auth}.json
```

## 5. 공개 API

화면 코드가 의존해도 되는 것은 `@/app/i18n` 배럴과 `react-i18next`의
`useTranslation`뿐이다. **`i18next` 인스턴스를 직접 import하지 않는다.**
나중에 구현을 교체하더라도 이 계약만 유지하면 화면 코드는 그대로 둔다.

```ts
SUPPORTED_LOCALES  // readonly ["ko", "en"]
DEFAULT_LOCALE     // "ko"
type Locale        // "ko" | "en"
isLocale(v)        // 외부 입력값 검증

initI18n()         // 진입점에서 렌더 전 1회
useLocale()        // { locale, setLocale }
<LocaleSwitcher /> // 언어 전환 UI
```

`applyLocale`은 배럴에서 노출하지 않는다. 언어 변경은 `useLocale().setLocale`
하나의 경로로만 일어나야 하며, 이 경로가 i18next 상태 · `localStorage` ·
`<html lang>` 세 가지를 한 번에 맞춘다.

## 6. 네임스페이스

| 네임스페이스 | 담는 것 |
| --- | --- |
| `common` | 화면에 무관한 공용 액션·상태 (`actions.save`, `status.comingSoon`) |
| `nav` | 사이드바 메뉴 라벨 (`groups.*`, `items.*`) |
| `auth` | 로그인 화면 |

`common`이 기본 네임스페이스다. 페이지가 늘어나면 **기능 단위로 네임스페이스를
추가**하고 `config.ts`의 `NAMESPACES`에 등록한다. 파일 하나가 비대해지지 않게
하는 것이 기준이며, 화면 개수가 아니라 응집도로 나눈다.

## 7. 타입 안전성

두 가지를 컴파일 시점에 잡는다. 둘 다 실제로 실패하는지 확인했다.

**(1) 존재하지 않는 키 사용** — `i18next.d.ts`가 기준 로케일(ko) JSON 구조를
`CustomTypeOptions.resources`로 선언한다. `t()`에 자동완성이 붙고 오타는
`TS2345`로 잡힌다.

**(2) 번역 누락** — `config.ts`의 `Mirror<T>` 타입과 `satisfies`가 ko 이외의
로케일에 ko의 모든 키가 존재하도록 강제한다. 누락 시 `TS1360`으로 잡힌다.
런타임 폴백에 기대지 않고 빌드에서 막는다.

## 8. 로딩과 오류 처리

- **로드 상태 없음.** 리소스가 전부 번들에 포함되므로
  `react: { useSuspense: false }`로 두고, 최초 렌더부터 번역이 준비된다.
  Suspense 경계나 스켈레톤이 필요 없다.
- **폴백.** `fallbackLng: "ko"`. 타입 가드를 우회한 경우에도 화면은 한국어를
  보여준다.
- **손상된 저장값.** `localStorage`에 지원하지 않는 값이 들어 있으면
  `isLocale`이 걸러내고 `DEFAULT_LOCALE`로 시작한다.
- **localStorage 접근 차단.** 프라이버시 모드 등에서 접근이 막혀도 예외를
  흘리지 않는다. 언어 선택이 해당 세션에만 적용된다.

## 9. 접근성

- `<html lang>`이 현재 언어를 항상 따라간다. 스크린 리더의 발음 선택과
  브라우저 번역 판단에 쓰이므로 화면 텍스트와 반드시 함께 바뀌어야 한다.
  `index.html`의 초기값을 `en`에서 `ko`로 고쳤고, 이후 `applyLocale`이 갱신한다.
- `LocaleSwitcher`는 `role="group"` + `aria-label`, 각 버튼에 `aria-pressed`.
  일반 `<button>`이므로 키보드 조작과 포커스 링은 공통 `Button`의 것을 그대로
  따른다.
- 언어 이름은 항상 해당 언어 자체로 표기한다(한국어 / English). 읽지 못하는
  언어로 적으면 전환 자체가 불가능해진다.

## 10. 함께 고친 결함

`sidebar.tsx`가 `openGroups` 상태의 키와 React `key`로 **번역 대상 문자열**
(`group.title`, `item.label`)을 쓰고 있었다. 이대로 두면 언어를 전환할 때
키가 전부 바뀌어 메뉴가 리마운트되고 펼쳐둔 그룹이 닫힌다.

`NavGroup`에 언어와 무관한 `id`를 추가하고, 상태 키와 React key를 `id` 및
번역 키(`labelKey`)로 바꿨다. 다국어 도입이 드러낸 결함이므로 이번 범위에
포함했다.

## 13. 남은 작업

- `src/pages/**`의 나머지 화면(약 20개)은 하드코딩 한국어 상태다.
  담당자가 화면을 손볼 때 기능 단위 네임스페이스를 추가하며 순차 전환한다.
- `react-router-dom`이 `dependencies`에 있으나 앱 전용이다. 커밋 `1487644`의
  기준과 어긋나므로 정리 대상이지만, 이번 범위 밖이라 건드리지 않았다.
